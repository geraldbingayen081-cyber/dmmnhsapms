1. Administrator (Admin) User Flowchart

System configuration, user management, load assignment, grade locking, institutional analytics, and DepEd reporting.

Key Process Highlights for Thesis Documentation
1. Academic Architecture Setup Defines foundational schemas: active School Years, Quarters (Q1-Q4), Grade Levels, Sections, and Curriculum Subjects.
2. User Provisioning & Matrix Assignment Manages account credentials and maps Subject Teachers to classes and Advisers to sections.
3. Grade Control & Locking Protocol Admin governs grade modification windows by locking/unlocking quarters to prevent unauthorized edits.
4. Institutional Analytics Engine Runs batch GPA calculations, honor roll filtering (DepEd criteria), and exports standard reports (SF9/SF10).

2. Teacher User Flowchart

Quarterly grade encoding, draft computation, advisory supervision, student monitoring, and report card generation.

Key Process Highlights for Thesis Documentation
1. Locking Status Verification Guarantees teachers can only input grades during authorized submission windows configured by the administrator.
2. Draft & Final Commit Workflow Enables teachers to save intermediate work incrementally or perform irreversible submission for administrative review.
3. Class Advisory Module Automatically computes section-wide general averages, flags students requiring academic intervention, and generates DepEd SF9.
4. Direct Parent Directory Access Empowers teachers to look up parent contacts directly for proactive feedback on student performance.

3. Student User Flowchart

Learner portal for tracking quarterly subject marks, GPA, academic honors qualification, and downloading electronic report cards.

Key Process Highlights for Thesis Documentation
1. Publication Gating Condition Protects confidential assessment records by only disclosing quarterly grades once officially verified and published by school administration.
2. Performance Visualizer Provides immediate visual analytics on subject strengths and areas needing academic improvement.
3. Electronic Report Card Generates verifiable, downloadable PDF grade slips (DepEd Form SF9 format).

4. Parent / Guardian User Flowchart

Parental monitoring portal with multi-child switching, early at-risk intervention warnings, and grade progress reports.

Key Process Highlights for Thesis Documentation
1. Multi-Child Switching Switcher Facilitates seamless context swapping between multiple siblings enrolled in the school from a single authenticated parent account.
2. Automated At-Risk Intervention Alert Evaluates subject grades against the passing benchmark (< 75) and triggers automatic parent consultation notices.
3. Faculty Contact Transparency Directly provides the advisory teacher and subject teachers' consultation details for timely parent-teacher collaboration.

6. Enterprise System Architecture (3-Tier Layered Model)

High-cohesion, low-coupling architectural paradigm detailing the Client Presentation Tier, Laravel 11/Livewire 3 Application Tier, and MySQL Persistence Tier.

3-Tier Architecture Principles & Technical Highlights
1. Presentation Tier (Client Layer) Driven by reactive Livewire 3 components and Blade templates with real-time DOM morphing, delivering a single-page app (SPA) user experience without full page reloads.
2. Application Tier (Business Logic Layer) Encapsulates critical business services including DepEd Grade Transmutation, Honors Engine (DepEd Order 36, s. 2016), At-Risk Early Warning, and Automated Document Generation (SF9/SF10).
3. Persistence Tier (Data & Storage Layer) Relational MySQL 8.0 schema governed by Eloquent ORM with foreign key integrity, atomic transactions for grade commits, and full audit logging for security compliance.

7. Entity Relationship Diagram (ERD) & Relational Schema

Comprehensive 18-entity database model detailing Primary/Foreign Keys, Unique Constraints, Cardinalities, and DepEd High School business logic.

Relational Architecture, Data Integrity & DepEd Specification Highlights
1. Core Fact Table (grades) Serves as the central transaction record for quarterly student assessments. Enforces strict uniqueness on (student_enrollment_id, section_subject_id, quarter_id), preventing duplicate submissions while storing computed quarterly marks, transmutation remarks, lock statuses, and author auditing.
2. Role-Segregated User Profiles The central users table encapsulates authentication credentials and RBAC roles ('admin', 'teacher', 'student', 'parent'). Specific academic and demographic attributes reside in dedicated profile entities (teachers, students, parents) with 1:1 foreign key relationships and cascade deletions.
3. Reusable Catalogs vs. Operational Instances Curriculum standards remain decoupled from annual rotations: sections and year_levels are reusable master templates, while school_year_sections instantiates active classroom units per school year with specific section advisers.
4. Class Scheduling & Advisory Matrix Section loads are partitioned via section_subjects, connecting classroom instances to subjects and assigned faculty teachers. Advisers manage the general roster and SF9 generation, whereas subject teachers encode subject grades independently.
5. DepEd Honors Engine (DepEd Order 36, s. 2016) achievement_rules models institutional honor thresholds (e.g., Minimum General Average ≥ 90.00, no failing grade in any learning area). The honors processor evaluates verified quarterly/final grades to persist awarded honors in achievements.
6. Comprehensive Audit Trail & Non-Repudiation The activity_logs table captures all security, grading, and configuration events. Stores polymorphic entity references (subject_type, subject_id) alongside JSON diff snapshots (old_values, new_values) for complete legal and administrative accountability.
